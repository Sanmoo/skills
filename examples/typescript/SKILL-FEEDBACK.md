# What the run exposed in the skill

Generating this example from `bootstrap-harness` exposed the gaps below; item 14 is the exception and surfaced when this record was reviewed. Each one was fed back into the skill files in the same change.

## Gaps and fixes

1. **Gate Proofs had no durable home.** The skill says to run them, but the inventory has no file that records the result, so the evidence disappears with the conversation. Fixed: [SKILL.md](../../skills/bootstrap-harness/SKILL.md) phase 7 now writes `GATE-PROOFS.md` next to the project, and this example does.
2. **The interview had no durable home either.** Phase 2 writes `GLOSSARY.md`, but the answers that shaped everything else (stack, edge, tools, defaults) only lived in the session. Fixed: [INTERVIEW.md](../../skills/bootstrap-harness/INTERVIEW.md) now asks for a recorded `INTERVIEW-ANSWERS.md` next to the project; this example links it from `README.md`.
3. **Per-context mutation thresholds need a wrapper.** GATE-CONTRACTS.md says 80% overall and 90% in core, but Stryker's `thresholds.break` is global. The example reads Stryker's JSON report in `scripts/check-mutation.mjs` and applies both limits. Fixed: [GATE-CONTRACTS.md](../../skills/bootstrap-harness/GATE-CONTRACTS.md) states that a tool without per-context thresholds needs a wrapper over its machine-readable report.
4. **"Changed relative to the base branch" hid uncommitted work.** A plain `git diff base...HEAD` excludes untracked files, so on day zero the Mutation Gate mutates nothing and passes. Fixed: the same contract now says the changed set includes the working tree and untracked files; the example's wrapper unions `git diff` and `git ls-files --others`.
5. **E2E needs a build and a readiness signal.** The contract says "built as it ships" but says nothing about the Entry Point building first or how a test knows the service is up. Fixed: the E2E contract now requires the Entry Point to build before the test level runs and the deliverable to expose a readiness signal. The example's e2e level was then deferred during review, so this fix is guidance here rather than something the tree demonstrates; `src/main.ts` still reports its port, which is the signal that level will wait for.
6. **Gate Proofs must be runnable again.** Repeating every proof by hand invites drift. This example keeps them in `scripts/gate-proofs.mjs`, each violation applied and reverted in one command. Fixed: phase 7 recommends an executable proof per Gate, while keeping the proof itself out of both Entry Points.
7. **A bare filename looked like a command.** "Every command a Guide names is one of the two Entry Points" is ambiguous: a backticked `eslint.config.mjs` starts with a tool name. Fixed: the Guide pointers contract defines a command as a tool name followed by an argument, and the example's Gate implements that.
8. **Avoided terms collided with API vocabulary.** `Instance` failed on `toBeInstanceOf`, forcing the glossary to drop a reasonable domain synonym. Fixed: the Avoided terms contract now warns that a term must be distinguishable from common API vocabulary, and the domain interview recommends choosing terms the ecosystem does not already use as identifiers.
9. **`exclude` silently disabled `pathNot` rules.** dependency-cruiser's `exclude` dropped `node_modules` targets, so the Dependency rule Gate passed while a domain imported `pg`. Fixed: the Context boundaries and Dependency rule contracts now say to use `doNotFollow` for third-party code, not `exclude`, when a rule relies on `pathNot`.
10. **Host binaries were missing from the blocker list.** Stryker's process cleanup shells out to `ps`; this container had no `procps`, so the Gate failed until a minimal `ps` shim was placed on `PATH` for the local run (CI's ubuntu runner has it). Fixed: the Blocked Gates section now asks for the host binaries a Gate needs, not only a container runtime and network.
11. **Test runner and mutation runner can drift.** The Dependency vulnerabilities Gate forced Vitest from 3.2.7 to 4.1.12 (a critical `tinypool` advisory), and the mutation runner had to keep working with it. Fixed: the stack interview now asks to verify the mutation tool supports the pinned test runner before locking versions.
12. **The lockfile must match the CI npm.** npm 10.9.8 crashed resolving Vitest's optional peers; the lock was generated with npm 11 and `npm ci` with npm 10 consumed it. Fixed: the version-pinning interview step notes that the lockfile should be produced by the npm version CI will use, or verified with it.
13. **The CI checkout made two Gates measure something else.** CI checks out almost no history, so the Secrets Gate scanned a single commit instead of the history its contract names, and the Mutation Gate could not resolve `main` and fell back to mutating the whole codebase on every pull request. On a push to the base branch it measured nothing at all, because the base tip was HEAD. Fixed: phase 5 now says what the CI checkout must give a Gate; the Mutation contract states that an unresolvable base is reported in the Gate's own output and widens the scope to the whole codebase, and that a base-tip HEAD measures what landed with the tip commit; this example's check workflow fetches full history, and `scripts/check-mutation.mjs` resolves `origin` before the other remotes, so a stale local branch cannot change the measured set and an extra remote is consulted only when `origin` does not carry the base. Widening is still a weaker measurement than the intended one, because a poorly tested changed file can ride a high whole-codebase average; the fallback fires only when the changed set cannot be established, which the checkout now makes the exception rather than the rule.
14. **"One at a time" was stated without its reason, so it reads as waste.** Phase 7 said to run each proof separately but not what the separation buys, which invites the reading that the same Entry Point is run N times for nothing. This one surfaced while the record on this page was reviewed rather than during the generation, and it is fixed the same way: phase 7 now says one violation per run is what makes the result attributable, because the Entry Point stops at the first Gate that fails, and this example's `scripts/gate-proofs.mjs` now refuses, before recording anything, the conditions under which a red Gate could not be attributed: a proof list that could not tell two Gates apart, a Gate an Entry Point runs without a proof, and a tree that was not clean when a proof started or did not survive one.

## Environment notes (not skill defects)

- The container had no `ps`; a minimal shim was used only to run Stryker locally. CI installs `procps` by default.
- Docker is available through the host socket; Testcontainers started pinned `postgres:17.2-alpine` containers without configuration.

## The acceptance run

This tree is the skill's acceptance test. It was generated on 2026-10-21 in a fresh session on the empty directory `examples/typescript/`, on branch `agent-issue-1` (born from `48efaa93e0c3936f369f36e33a202267a34aca8e`), with the interview answers fixed by the issue and recorded in [INTERVIEW-ANSWERS.md](INTERVIEW-ANSWERS.md). The empty start is verifiable: `git ls-tree 48efaa93e0c3936f369f36e33a202267a34aca8e examples` returns nothing, so the directory did not exist at the fixed point. The session ran every Gate Proof in [GATE-PROOFS.md](GATE-PROOFS.md), then both Entry Points: `make check-fast` offline and `make check` with containers, mutation, and the advisory database. Both were green on the final tree.

One departure came afterwards, from review rather than from the run: the e2e tests were removed and the E2E Gate deferred to a Cucumber/Gherkin rewrite, so this tree has no E2E Gate and no proof for that Contract. [ADR 0003](docs/adr/0003-defer-the-e2e-level.md) records the decision, [INTERVIEW-ANSWERS.md](INTERVIEW-ANSWERS.md) the deferred level, and [GATE-PROOFS.md](GATE-PROOFS.md) the Contract with no row. Afterwards, [Sanmoo/skills#6](https://github.com/Sanmoo/skills/issues/6) settled the universal Gherkin rule, and [ADR 0004](docs/adr/0004-defer-the-e2e-level-under-the-universal-rule.md) now carries the deferral and supersedes ADR 0003.

That departure exposed a gap this round did not close: the skill has no vocabulary for a deliberately deferred Gate Contract. Phase 7 asks for a proof row per Gate, the Gate Floor says every project has all of them from day zero, and the blocked-Gates rule covers only the environment, so a project that postpones one Contract either leaves a row missing or fakes a proof. Amending that is a harness decision of its own, with its own Gate Proof, so it is recorded here as the run's last open gap rather than fixed in this change.
