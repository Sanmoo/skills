# Tolerate specific legacy debt without allowing regression

## Context

The adoption path added in [ADR 0002](0002-adoption-path.md) accepts existing findings so a debt-bearing application can reach an established Harness, but [GATE-CONTRACTS.md](../../skills/bootstrap-harness/GATE-CONTRACTS.md) left the shape of that acceptance open. A count, a directory, or a stored set a tool regenerates can absorb a new violation behind a removed one, and a failing suite can drift into an accepted count of failures. The application's observed behavior, not its business correctness, is what adoption must preserve. [Sanmoo/skills#15](https://github.com/Sanmoo/skills/issues/15) asked for adoption that tolerates the debt an application already carries without letting a new or aggravated violation hide behind it.

## Considered Options

- **A count or percentage per Gate, regenerated by a run**: rejected because a new violation disappears behind a fixed one and the tolerance policy drifts without a reviewed change.
- **Path, rule, or severity exclusions as tolerated findings**: rejected because they hide new code and new rules at the accepted place.
- **Require eliminating debt before establishment or before touching debt-bearing code**: rejected because it turns adoption into a rewrite of code whose behavior is the regression contract.
- **A risk register with owners and expiry dates**: rejected because it adds governance the work does not need; the reviewed change to the tolerance policy is the decision record.
- **Correct observed behavior automatically when it looks wrong**: rejected because the regression tests characterize what the application does; only a localized human decision may change that.

## Decision

Accept existing debt only as specific tolerated findings in each Gate's tolerance policy, matched one to one with the reported findings, so a new, grown, or returned violation fails - except a security finding an explicit human decision tolerates, as the Contract requires - and a stale entry fails until a reviewed change tightens it; new code keeps the Contract's normal limits, and changing debt-bearing code only has to avoid worsening its findings. The Contract also states what keeps a finding from being reported at all: an exclusion is declared scope with a stated reason, may cover third-party, generated or non-production targets, and never follows a finding the Gate already reported, so scope cannot stand in for tolerance. [GATE-CONTRACTS.md](../../skills/bootstrap-harness/GATE-CONTRACTS.md#tolerated-findings) holds the tolerance and security rules, including the absence of any owner or expiry, and [its observed-behavior rules](../../skills/bootstrap-harness/GATE-CONTRACTS.md#observed-behavior) hold the treatment of failing suites and localized decisions. [ADR 0003](0003-execute-adoption-to-establishment.md) remains in force; this ADR defines the tolerance policy its criteria accept.
