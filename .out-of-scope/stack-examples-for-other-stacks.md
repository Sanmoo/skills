# Stack Examples for other stacks

The request was to add more non-normative Stack Examples beside the TypeScript
one, for stacks such as Kotlin/JVM, Go, and Elixir, each generated by
`bootstrap-harness` and checked by this repository's CI.

The project declines this.

## Why this is out of scope

A Stack Example is a full Harness: a Walking Skeleton, every Gate in the Gate
Floor wired with pinned tools, the Guides, and one Gate Proof per Gate run
against a real environment. Each additional stack therefore costs a complete
`bootstrap-harness` run plus a complete Gate Proof run — containers, network for
the advisory database, and whatever host binaries the chosen tools shell out to
— and then a CI job and a proof workflow of its own to keep it honest.

What that buys is a second realization of the same Gate Contracts, not more
evidence about the Contracts themselves. The Contracts are the authority and are
stack-agnostic by construction; the TypeScript example already exercises every
one of them end to end, including the contracts that were hardest to satisfy:
per-context mutation thresholds, the changed-set mutation scope, the readiness
signal the e2e level waits on, and the CI checkout each Gate needs. A second
example would restate that coverage in a different language at a cost of one
full harness per stack.

The asymmetry is deliberate: the Contracts carry the universal obligations, and
an example carries only how one stack meets them. When a Contract is wrong, the
fix belongs in the Contract, and the TypeScript example is enough to show the
fix is realizable.

## When to revisit

Reopen this if the Contracts gain an obligation the TypeScript example cannot
exercise — an obligation whose realizability depends on a stack family rather
than on a tool choice — because that is a claim only a second example can test.
Adding a stack for its own sake is not that.
